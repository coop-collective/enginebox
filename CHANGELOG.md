# Changes

## Unreleased

- **Agent forks on live engine sessions (controller).** Room members run their own Claude Code or Codex agent on a fork of a live editor session's dev tree and submit it back: `…/engine-sessions/{sid}/forks` (create, list, read, diff, runs, run events, cancel, submit, rebase, close), `…/submissions` (list, approve, reject), `…/dev` (head, applied, held, compile state, live code edits, notices), `…/dev/revert` and `…/dev/publish`. Submissions are classified by path (refused, protected, code, config, scene, asset) and secret-scanned; code and protected paths wait for the room owner, scene, asset and config merge automatically; a merge that breaks compilation is reverted automatically with the compiler errors recorded for the author and owner. Limits: 3 open forks per person, 3 concurrent runs per machine (round robin by person), $2 default run budget ($20 max), 30-minute runs. Model access is each person's own Xava Inference connection: Engine Box is an OAuth client of xinf (`…/gateway/connect`, callback `/v1/gateway/xinf/callback`, or a pasted `xk_live_` key), tokens sealed with AES-256-GCM and delivered to the node only for a run in flight; configure the platform `xava-inference` connection. The new OAuth scope `agent-forks` grants it; apps that register an Ed25519 `enginebox_principal_key` can vouch for signed-in room members per request (signed, 60 s, single-use assertions on agent-fork routes only). The node channel gains fork ops in `engine-poll`, `fork-report`, `fork-events`, `fork-artifact` and `engine-report`'s `detail.dev` (node and supervisor routes included; the node side ships separately). Audited as `agent_fork.*` ([agent forks](docs/ENGINE-SESSIONS.md#agent-forks-packagesenginebox-controllersrcagent_forks), [OAuth](docs/OAUTH.md#agent-forks)).

- **World sessions.** Engine sessions accept `mode:"world"` with `world:{room_origin, enroll_code}` to run a room's world host (Gamejam's `gamejam-world-host`) instead of the Editor: the node checks out and activates Unity as before, then starts the `world_host` named in `engine.json` with an owner-only `--session` file, is ready on its `{"event":"world-host-connected"}` line, restarts it like the stream host, and keeps player builds in `work\engine\world-builds` across sessions. The enrollment code lives only in controller memory and the node's secrets. OAuth apps may name only rooms the owner lists in the `engine-world-<project>` connection's `ROOM_ORIGINS`; the owner token may name any https origin. No MoQ relay is created; `POST /v1/projects/{p}/engine-sessions/{id}/ice {}` (`engine_sessions.watch`, also on the public OAuth origin) returns relay-only Cloudflare TURN ICE servers. Starts are audited as `engine.world_start`; the heartbeat reports `tools.engine.world` ([world sessions](docs/ENGINE-SESSIONS.md#world-sessions-mode-world)).

- **Engine sessions open the full Unity Editor.** Sessions no longer auto-enter Play mode with a play-only bridge: Unity opens in the Editor (Scene view), the session is ready once the editor bridge answers and has compiled, and the stream host runs the full editor bridge (`capture.editor: true`), so the controlling client can switch between the Editor and Play mode, save the scene and use the hierarchy and Inspector ([Windows executor](docs/ENGINE-SESSIONS.md#windows-executor-packagesenginebox-installsrcenginers)).

- **WebRTC fallback for engine-session viewers.** Viewers whose network blocks QUIC (UDP 443, as some VPNs do) can watch and control over WebRTC relayed through Cloudflare TURN (including TLS on 443): `POST /v1/projects/{p}/engine-sessions/{id}/peers` opens a peer (`watch`, or `control` for the starter), then one offer and one answer pass through the controller; the stream host signals with a per-session host token through `/api/node/engine-peers/…`. Needs the platform `cloudflare-turn` connection (`TURN_KEY_ID`, `TURN_API_TOKEN`); MoQ stays primary and engine machines still open no port ([WebRTC fallback](docs/ENGINE-SESSIONS.md#webrtc-fallback-packagesenginebox-controllersrcengine_sessionspeersrs-turnrs)).

- **Engine node: the editor bridge port recovers from conflicts.** If another program takes the loopback port picked for the Unity editor bridge before Unity binds it, the node writes a new free port into `bridge.json` (the bridge retries and re-reads it) after about 6 s, up to five times, and the stream host is always started against the port the bridge is answering on ([Windows executor](docs/ENGINE-SESSIONS.md#windows-executor-packagesenginebox-installsrcenginers)).

- **Per-session MoQ relays and public watch tokens.** With `CLOUDFLARE_MOQ_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` on the platform `cloudflare-moq` connection, every engine session gets its own Cloudflare MoQ relay: the node publishes with a token for that relay only, the starter's stream block carries that relay's subscribe and control tokens, and `POST /v1/projects/{p}/engine-sessions/{id}/watch-token` returns a 30-minute subscribe-only token (no control) for public viewers, callable by the owner, the starter, or an OAuth token with the new `engine_sessions.watch` operation. The relay is deleted when the session ends, fails or is lost; a relay that cannot be created fails the start instead of falling back to the shared relay. Relay and token ids are recorded in `engine-sessions/relays/`, never a token ([per-session relays](docs/ENGINE-SESSIONS.md#per-session-relays-packagesenginebox-controllersrcmoqrs)).

- **Engine sessions over OAuth.** Connected apps (Gamejam's hosted room) start, read, renew and end engine sessions through the public origin with the new `engine-sessions` scope (`agent-runs` stays the default; existing clients are unchanged). The consenting member ticks "Run live engine sessions in project X"; any member may approve an engine-sessions-only grant. Tokens carry `engine_sessions: [{project}]`, `member` and `engine_sessions.start|get|renew|end`; the controller acts as that member from the token (never a header), so starts use their own engine machine and Unity account and only their reads carry the stream block; other members' sessions and the owner-wide routes stay closed. `enginebox_grants` adds `{kind:"engine_sessions", project, member}`; a member who leaves the org ends the connection at refresh ([OAuth](docs/OAUTH.md#engine-sessions), [engine sessions](docs/ENGINE-SESSIONS.md#who-can-call-it)).

- **Engine sessions v1.** A member starts the Unity Editor for a repository on their own Windows engine machine and gets a MoQ stream back: `POST/GET /v1/projects/{p}/engine-sessions`, renew and end (owner token and members through the dashboard; OAuth below). Sessions are placed only on the starting member's claimed engine machine, fenced by node epoch and session generation over a new `engine-poll`/`engine-report` channel beside the job slot, and receive a repository read token, the member's Unity access token and the relay publish token only on that node and epoch. The node checks out the ref with Git LFS, adds the Gamejam editor bridge, activates Unity, starts the Editor in Play mode and runs the stream host, all in a per-session Job Object; owners configure `engine.json` and the platform `cloudflare-moq` connection ([engine sessions](docs/ENGINE-SESSIONS.md#what-v1-implements-november-1-2026)).

- **Unity accounts.** Each member saves one Unity ID email and password per org on **Agents → Unity account**. The controller signs in with Unity when it is saved or updated: a wrong password or a two-factor account is refused, and an account Unity could not check is saved as unverified. The password is write-only. Sessions a member starts will use only their own Unity license, through a short-lived access token (`Credentials::unity_access_token`) rather than the password ([Unity accounts](docs/ORGS.md#unity-accounts)).

- **License.** New versions move from Sustainable Use License 1.0 to the Business Source License 1.1. Personal, non-commercial and non-production use is free; production business use requires a commercial license at $10 per node per month; hosted or managed service offerings require a separate agreement. Each version converts to Apache-2.0 four years after its first public release. Earlier versions keep their licenses; the Sustainable Use License text moved to `LICENSE-SUSTAINABLE-USE-1.0`. See [licensing](docs/LICENSING.md).

- **Project repositories.** Hosted Git repositories per project backed by Cloudflare Artifacts (beta) through a new Artifacts gateway Worker (`packages/artifacts-gateway`) that holds the Artifacts bindings and accepts only HMAC-signed, replay-protected controller requests (no Cloudflare API token is stored); an owner-only, write-only backend configuration; create (idempotent), list, read and short-lived token routes; per-project `repositories` grants for service tokens and OAuth consent; and runs that name a repository receive a write token at admission as a git header scoped to that remote, revoked when the run ends. A backend interface leaves room for a GitHub App backend ([repositories](docs/REPOSITORIES.md)).

- **Copy-on-write disk admission.** Hosts whose admission pool uses btrfs or zfs (reported as `pool_driver` by the host inventory) now admit against actual pool usage after `reserve_disk_gib`, with allocated sizes capped at `(pool_total - reserve) * disk_overcommit` (default 4.0; 1.0 and strict for other drivers). New optional host keys `disk_accounting` and `disk_overcommit`; disk refusals show both guards; `GET /v1/fleet` reports the driver, mode and budgets plus a read-only `stale_instances` list ([fleet](docs/FLEET.md)).

## 0.3.0 — development preview

Notable changes since 0.2.0, grouped from the commit history. Everything below remains a single-owner development preview; see the linked guides for what is qualified versus planned.

- **Rust runtime.** The runtime moved to native Rust packages with supervised, version-pinned release updates and retained-version rollback ([Rust migration](docs/RUST-MIGRATION.md), [updates](docs/UPDATES.md)). Native agent workspaces are preserved across the migration; Windows private-path and ACL handling and bounded command pipe draining were fixed.
- **LayerFS storage.** Opt-in LayerFS checkout backend managed through fleet tools, writable Incus checkouts exported through virtiofs, interrupted-command and daemon recovery, large Unreal project restore and merge qualification, and a choice of LayerFS container workspaces ([LayerFS](docs/LAYERFS-BACKEND.md), [game workspaces](docs/GAME-WORKSPACES.md)).
- **Cloudflare fleet.** Local Wrangler fleet with Durable Object authority, recoverable Store transport, R2 storage and candidate CI gates, with the design requiring Cloudflare fleet authority and optional storage nodes ([local fleet](docs/LOCAL-FLEET.md)).
- **Tasks and agents.** Durable project tasks with scoped native MCP tools, native Codex task-assistant dispatch, separation of model task credentials from trusted executor identities, and fencing of uncertain native runs before a restarted node advertises capacity ([task workflow](docs/TASK-WORKFLOW.md), [task assistant](docs/TASK-ASSISTANT.md)).
- **GitHub.** LayerFS-owned GitHub import and guarded main sync ([GitHub sync](docs/GITHUB-SYNC.md)).
- **ACP and CLI.** ACP control and a live native-agent fleet task CLI (`ebox tasks`, `ebox acp`) ([ACP](docs/ACP.md)).
- **Native clients.** Current Cursor CLI qualified with rejection of native version drift; explicit Cursor Cloud model probes recorded.
- **Site and layout.** Product site and developer guides; standalone research separated from product packages ([research](research/README.md)).
- **Measurements.** Rust VM boot benchmarks and remote agent timing campaigns; see [reports](docs/reports/VALIDATION.md).

## 0.2.0 — development preview

This release brings the portable-fleet development branch into the main repository and changes the license for new work to Sustainable Use License 1.0. Earlier Apache-2.0 grants remain valid; see [licensing](docs/LICENSING.md).

- Controller-managed native agent connections, automatically synchronized templates and private prepared workspace pools.
- Dedicated Fleet, Agents and Templates sidebar views.
- Operator MCP/API launch and polling for native Codex, Claude and Cursor runs, exact native session resume, private persistent workspace homes and bounded execution.
- Scoped Ubuntu sandbox preparation for Cursor's native helper, model-free readiness checks and updated native template recipes.
- Usage cards with read-only native Codex allowance/reset observations, stale-data handling and explicit unavailable billing data.
- Read-only portable host/resource/GPU discovery and explicit CPU/RAM contribution ceilings for the existing Linux backend.
- Test-gated Python wheel/source package builds, package notices and clean-environment installation checks.

This remains a single-owner development preview. Public multi-tenancy, movable tenant state volumes, Docker laptop enrollment, Windows/macOS native workers, GPU scheduling and Windows/macOS guest images remain unimplemented. Independent fresh-host installation, signed platform installers and upgrade/backup qualification remain release gates. Test fixtures do not establish hardware support or provider inference; exact observed validation is recorded in [VALIDATION.md](docs/reports/VALIDATION.md).
